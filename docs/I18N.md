# English and 简体中文 (Issue #74)

English | [简体中文](I18N.zh-CN.md)

The interface can be shown in English or Simplified Chinese. The switcher is in the header bar on
wide screens, inside the header menu on phones (#166), and on the Settings page. The choice is stored in `localStorage`
as `locale`, next to `theme`, and restored before the app first renders, so a returning visitor
never sees the English pages flash past. English is the default; the browser's own language is
not used to pick Chinese unasked.

## How it works

Two layers sit behind one switch:

| Layer | Used for | Files |
|---|---|---|
| Keyed messages (vue-i18n) | Navigation, footer, theme menu, sign-in, registration, password reset, Settings, the account dialogs, password and passphrase rules | `frontend/src/locales/en.json`, `zh-CN.json` |
| Dictionary | Everything else written in English in the templates and scripts | `frontend/src/locales/ui-strings.json`, `zh-CN.dict.json` |

The dictionary layer (`frontend/src/i18n/dom-translate.ts`) replaces a text node or a readable
attribute (`placeholder`, `title`, `aria-label`, `alt`) whose whole text is an entry. Text with
values in it matches a pattern entry: `Resend in 42s` matches `Resend in {0}s`, and the `42` is
kept as shown. It was chosen over rewriting every component around keys because it covers the
whole interface for a fraction of the change; the cost is that a sentence split by a link or a
bold word is translated in pieces, and text built at run time out of several parts may stay
English.

Both Chinese files are loaded as one lazy chunk, only by visitors who choose Chinese.

## What is never translated

- Anything inside an element marked `translate="no"`: file names, folder names, usernames,
  email addresses, recovery reasons, Help assistant questions, hashes. **Mark new user content
  the same way** wherever it is rendered.
- `<code>`, `<pre>`, `<textarea>`, form values.
- Algorithm names (AES-256-GCM, SHA-256, RSA-OAEP, Argon2id, nonce…), `.pem`, `.ciphertext`,
  API error codes, audit-log evidence.

## Updating the Chinese

1. After changing English text, regenerate the list (a unit test fails until you do). A string
   the extractor cannot recognise (one starting with a number, like `14 rounds`) goes in
   `ui-strings.extra.json` by hand. `node scripts/find-untranslated.mjs` lists the English still
   showing on the public pages in Chinese.

   ```bash
   cd frontend && node scripts/extract-ui-strings.mjs
   ```

2. Draft the new strings where the Zhipu key is. The script needs only Python's standard library
   and sends only strings not yet in `zh-CN.dict.json`, so a small change costs a few requests.
   The key is never committed and never printed.

   ```bash
   TRANSLATE_LLM_KEY=... python3 frontend/scripts/translate_ui_strings.py
   ```

   On the staging VPS the key is the one Monash Hub already uses, in `/opt/monash-hub/repo/.env`;
   copy `scripts/translate_ui_strings.py` and the four locale files to a scratch directory, run it
   with `--locales <dir>`, and copy `zh-CN.dict.json` and `zh-CN.json` back.

3. Read the diff of `zh-CN.dict.json` before merging. Correct an entry by editing it; a re-run
   never overwrites an existing entry.

Every reply is checked before it is kept: placeholders and plural bars unchanged, algorithm names
kept, and the glossary below. A string that fails twice stays English and is listed at the end
of the run. `src/i18n/i18n.test.ts` checks the same glossary, key parity between `en.json` and
`zh-CN.json`, that every message compiles, and that every key the code uses exists.

## Glossary

| English | 中文 |
|---|---|
| password | 登录密码 / 密码 |
| encryption passphrase | 加密口令 |
| private key / public key | 私钥 / 公钥 |
| private key file | 私钥文件 |
| key file | 密钥文件 |
| recovery request | 恢复请求 |
| share / revoke | 分享 / 撤销 |
| integrity check | 完整性检查 |
| ciphertext | 密文 (the `.ciphertext` extension stays) |

A login password is never called 口令, and a passphrase is never called 密码.

## Known limits

- **The Chinese is machine-drafted.** Scripts and tests enforce the glossary, but no person has
  reviewed every entry. Treat a wrong translation as a bug and fix the entry.
- The Help assistant matches questions in English only; a question typed in Chinese gets the
  fallback answer.
- Captions burned into the walkthrough videos stay English.
- Dates and numbers keep their existing formats.
