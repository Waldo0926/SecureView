## 怎么看这些 429

所有请求都从家里的同一个地址经公网 URL 发出，和真实用户走一样的路径：HTTPS、nginx、再到 API。限流全程开着。429 说明限制按设计起作用了，不是服务器出错：

| 429 来源 | 次数 | 出现在 |
| --- | ---: | --- |
| nginx，每个地址最多 50 个上传同时进行 | 644 | 两次 100 用户步骤（323 + 321） |
| nginx，每个地址每秒 30 个 API 请求 | 1 | 第二次 100 用户步骤里的一次下载 |
| Argon2id 同时 2 个的限制和 nginx 每分钟 60 次凭证校验 | 68 | 同时 4、8、16 人登录的测试 |
| **合计** | **713** | |

唯一的 413 是每个账号 2 GiB 的存储配额。大文件测试把 pdf 交给了 001 号账号，它在前面的步骤里已经存了 1,692 MiB 的 1 MiB 文件，再放 500 MiB 的 pdf 就会超过 2 GiB，配额拒绝了它，这是对的。随后用一个几乎空的账号把同一个文件重新跑了一遍，逐字节一致（`raw/sizes-20261009T144951Z`）。工具里的大文件测试现在会按类型各用一个账号，但这次运行复用了前面步骤用过的头几个账号。

## 测试条件

- **压测机：** 一台 MacBook，家里宽带，走公网 URL。这次没有用 SSH 隧道。为了和 10 月 3 日完全同条件对比，考虑过再走隧道直连 API 跑一轮，但没有做：那需要临时改生产服务器的 sshd 配置，而公网路径的结果已经能回答问题。
- **限流全程开着：** nginx 每个地址每秒 30 个请求（突发 60）、每分钟 60 次凭证校验（突发 30）、每个地址 50 个同时上传，以及每个账号 2 GiB 存储和每天 5 GiB 上传的配额。为了不超配额，大文件测试按类型各用一个账号，每个文件验证完就删除。
- **账号：** 用 `seed_load_users.py` 建的 100 个一次性账号 `loadtest-e4d76a-*`，结束后全部通过 API 删除（`cleanup`），文件也一起删了。演示账号没有用到。
- **服务器没有暂停定时任务：** 压测期间没有碰上备份和巡检（04:15 和 05:30），CI runner 也是空闲的。
- **同一晚实测的网速（到 Cloudflare）：** VPS 网口下行 94 Mbit/s、上行 97 Mbit/s；MacBook 单连接下行 62 到 132 Mbit/s、上行 475 Mbit/s，用 speedtest.net 多连接测到吉隆坡服务器是下行 821 Mbit/s、上行 493 Mbit/s。每个 500 MiB 文件上传约 87 到 88 Mbit/s（约 48 秒），下载约 96 到 98 Mbit/s（约 43 秒），也就是单个传输就能把 VPS 的 100 Mbit/s 网口跑满。下面大小表格里的 MiB/s 一列只有 3.4 到 3.7，是因为它用总字节除以整个步骤的时间，里面还包括分享、删除和客户端自己加密的时间。
