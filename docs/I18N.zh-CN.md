# 英文与简体中文（Issue #74）

[English](I18N.md) | 简体中文

界面可以用英文或简体中文显示。宽屏时切换入口在页头栏，手机上在页头菜单里（#166），设置页也可以切换。选择以 `locale`
存在 `localStorage`，与 `theme` 并列，并在应用首次渲染前恢复，所以回访用户不会先看到英文页面一闪而过。
默认英文，不会因为浏览器语言自动切成中文。

## 工作方式

一个开关背后有两层：

| 层 | 用于 | 文件 |
|---|---|---|
| 键值消息（vue-i18n） | 导航、页脚、主题菜单、登录、注册、重置密码、设置页、账户对话框、密码与 passphrase 规则 | `frontend/src/locales/en.json`、`zh-CN.json` |
| 词典 | 模板和脚本里其余所有英文 | `frontend/src/locales/ui-strings.json`、`zh-CN.dict.json` |

词典层（`frontend/src/i18n/dom-translate.ts`）会替换整段文字恰好是词条的文本节点或可读属性
（`placeholder`、`title`、`aria-label`、`alt`）。带数值的文字按模式词条匹配：`Resend in 42s` 匹配
`Resend in {0}s`，`42` 原样保留。之所以选它而不是把每个组件都改成键值写法，是因为它用很小的改动就覆盖了
整个界面；代价是被链接或粗体拆开的句子会分段翻译，运行时由多段拼出来的文字可能仍是英文。

两份中文文件合成一个懒加载分块，只有选择中文的访客才会下载。

## 永远不翻译的内容

- 标记了 `translate="no"` 的元素里的一切：文件名、文件夹名、用户名、邮箱地址、恢复理由、问答助手的
  问题、哈希值。**新增用户内容时在渲染处同样加上这个标记。**
- `<code>`、`<pre>`、`<textarea>`、表单值。
- 算法名（AES-256-GCM、SHA-256、RSA-OAEP、Argon2id、nonce……）、`.pem`、`.ciphertext`、API 错误码、
  审计日志证据。

## 更新中文

1. 改完英文后重新生成词条列表（不重新生成，单元测试会失败）。提取器识别不了的字符串（以数字开头的，
   如 `14 rounds`）手动加到 `ui-strings.extra.json`。`node scripts/find-untranslated.mjs` 会列出中文模式下
   公开页面上仍显示的英文。

   ```bash
   cd frontend && node scripts/extract-ui-strings.mjs
   ```

2. 在有智谱密钥的地方生成新词条的初稿。脚本只用 Python 标准库，只发送 `zh-CN.dict.json` 里还没有的
   字符串，所以小改动只需几次请求。密钥从不提交、从不打印。

   ```bash
   TRANSLATE_LLM_KEY=... python3 frontend/scripts/translate_ui_strings.py
   ```

   在 staging VPS 上，密钥就是 Monash Hub 已在用的那个，位于 `/opt/monash-hub/repo/.env`；把
   `scripts/translate_ui_strings.py` 和四个语言文件复制到临时目录，用 `--locales <dir>` 运行，再把
   `zh-CN.dict.json` 和 `zh-CN.json` 复制回来。

3. 合并前读一遍 `zh-CN.dict.json` 的 diff。发现错误就直接改词条；重新运行脚本不会覆盖已有词条。

每条回复保存前都会检查：占位符和复数分隔符不变、算法名保留、符合下面的术语表。连续两次不合格的字符串
保持英文，并在运行结束时列出。`src/i18n/i18n.test.ts` 检查同一份术语表、`en.json` 与 `zh-CN.json`
的键是否一致、每条消息能否编译，以及代码用到的每个键是否存在。

## 术语表

| English | 中文 |
|---|---|
| password | 登录密码 / 密码 |
| encryption passphrase | 加密口令 |
| private key / public key | 私钥 / 公钥 |
| private key file | 私钥文件 |
| key file | 密钥文件 |
| recovery request | 恢复请求 |
| share / revoke | 分享 / 撤销 |
| integrity check | 完整性检查 |
| ciphertext | 密文（`.ciphertext` 扩展名保留） |

登录密码从不叫“口令”，passphrase 从不叫“密码”。

## 已知限制

- **中文是机器起草的。** 脚本和测试会强制执行术语表，但没有人逐条审过。把错误翻译当作 bug，直接改词条。
- 问答助手只匹配英文问题；用中文提问会得到兜底回答。
- 演示视频里烧录的字幕仍是英文。
- 日期和数字保持原有格式。
